# 自動更新完了後の即時再起動 設計

## 背景

MacClipy はメニューバー常駐アプリであり、通常は長期間終了されない。現在の Sparkle 標準挙動では、自動ダウンロードした更新はアプリ終了時までインストールを待つため、最新版の適用が長期間遅れる可能性がある。

## 目的

「更新を自動でダウンロード/インストール」が有効な場合、通常更新のダウンロードとインストール準備が完了した直後に、MacClipy を無通知で自動インストール・再起動する。

## 対象範囲

- Sparkle がバックグラウンドで自動ダウンロードした通常更新を対象とする。
- ダウンロード、署名検証、展開など、Sparkle が即時インストール可能と判断するまでの処理は変更しない。
- 手動の「アップデートを確認...」の操作と表示は変更しない。
- メジャーアップデート、情報提供のみの更新、署名検証に問題がある更新など、Sparkle がダウンロード前にユーザー確認を要求する更新は対象外とする。

## 動作

1. Sparkle の自動確認が通常更新を検出する。
2. 「更新を自動でダウンロード/インストール」が有効な場合、Sparkle が更新をバックグラウンドでダウンロードする。
3. Sparkle が署名検証と展開を完了し、終了時インストールを予約する段階に到達する。
4. MacClipy は Sparkle から渡される即時インストール処理を直ちに実行する。
5. Sparkle が MacClipy を終了し、更新をインストールして自動的に再起動する。

再起動前の通知、確認画面、カウントダウン、延期操作は設けない。

## 実装方針

- `SPUUpdaterDelegate` に準拠する専用の小さな delegate を追加する。
- `updater(_:willInstallUpdateOnQuit:immediateInstallationBlock:)` で即時インストール処理を呼び出し、`true` を返して処理を引き受ける。
- `AppUpdater` が delegate を強参照し、`SPUStandardUpdaterController` の初期化時に渡す。
- Sparkle のダウンロード・検証・インストール・再起動機構をそのまま利用し、独自の終了処理や更新状態監視は追加しない。

## エラー処理

- ダウンロード、署名検証、展開が失敗した場合は即時インストール用 delegate が呼ばれないため、再起動しない。
- インストール開始後の失敗は Sparkle の既存エラー処理に委ねる。
- 自動更新が無効な場合は現状どおり自動ダウンロードも自動再起動も行わない。

## テスト

- delegate が即時インストール処理を呼び出すことを単体テストする。
- delegate が Sparkle に処理を引き受けたことを示す `true` を返すことを単体テストする。
- 既存の更新設定とメニュー操作に回帰がないことを既存テストで確認する。
- `swift test` と `scripts/check.sh` を実行する。

## 受け入れ条件

- 自動ダウンロードした通常更新の準備完了後、アプリを手動終了しなくてもインストールが始まる。
- インストール時に確認画面や通知を表示しない。
- インストール完了後、MacClipy が自動的に再起動する。
- 手動更新とユーザー確認が必要な更新の既存挙動を変更しない。
